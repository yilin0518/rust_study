# 一年后端就业路线

更新日期：2026-10-13。目标：互联网公司通用后端开发实习及校园招聘，保留系统与基础设施方向。公司名单是投递目标，不代表项目完成后必然获得录用。

## 当前选择

- 第一项目语言：Rust；工程栈：Tokio、Axum、MySQL、SQLx、Redis、Linux、Docker。借 Mini Order Service 建立完整后端知识模型。
- 算法语言：C++，另设工程语言能力复查，不能将刷题等同于 C++ 后台开发经验。
- 当前开始完整业务后端，不再以完成 Redis Clone 的复制、事务等高级功能作为前置条件。
- 已有 Echo、Future、Mini Redis 作为补充实验，遇到相关问题时回访。
- 第二项目确定采用 Go，Rust 核心验收后开始。暂定团队协作与工单服务，进入阶段时确认具体业务；不要求先用两种语言完整重写同一项目。
- 当前集中完成 Rust，不同时开展 Go 项目。岗位复查用于调整 Go 阶段重点与投递策略；Java 不是预设第三条主线。
- SQL、HTTP、事务、可靠性等能力通过实践迁移；语言生态、运行时、测试和调试能力要单独验证。

## 阶段路线

| 阶段 | 主任务 | 可审查成果 | 进入下一阶段的条件 |
|---|---|---|---|
| 月 1～3 / Week 1～12 | Rust Mini Order Service、C++ 算法、网络/OS/MySQL/Redis、初步投递 | HTTP/SQL/事务/并发/权限/缓存核心路径、自动化测试、部署、基线与故障证据；可靠任务按容量推进 | 达到 [Rust → Go 切换门槛](go_project_phase.md)，核心路径可独立修改和解释 |
| 月 4～6 / Week 13～24 | Go 基础与工程方式，第二个 Go 后端项目；持续投递与面试复盘 | Go 工单服务的业务、权限、事务、并发、测试、部署与可靠通知；Rust 保留维护 | 能独立用 Go 实现完整业务路径，解释 context/并发/数据库边界与两种实现方式的差别 |
| 月 7～9 / Week 25～36 | 优先实际实习与工程协作；无实习则选一条系统扩展 | 小型真实贡献、Code Review/排障记录；或 Rust Gateway/可靠通知模块之一 | 能从现象收集证据定位根因，独立修改关键路径 |
| 月 10～12 / Week 37～52 | 校招/后续实习、算法与项目深挖、专项强化 | 简历、两段深入项目叙述、故障和性能案例、模拟面试与申请记录 | 根据目标岗位实际反馈调整，不以学完技术清单作为终点 |

月数和周数是预算，不是已完成进度。研究任务较重时缩减扩展项、延长阶段；缺少关键正确性证据时先修复核心路径。

## 求职与阶段检查点

第 1 周收集 10～15 个具体岗位，不只记录公司名称。填写岗位链接、地区、实习/校招类型、毕业年份要求、语言硬性条件、到岗时间、每周天数、持续月份及更新时间。导师/学校是否允许实习由学习者确认，不能推定满足条件。

第 4～6 周分类：

1. 接受多语言/更关注基础能力：用 Rust 项目的事务、测试、排障与独立设计争取早期机会。
2. 明确 Go 要求：记录框架、数据库和工程能力缺口，为确定的 Go 阶段选择重点；当前不因清单变化同时开启第二项目。
3. 明确 Java 或 C++ 工程要求：决定是否暂缓该岗位，或是否值得另行补课；C++ 算法训练不自动等于后台工程经验。

第 6 周起，具备核心服务演示、基本算法与基础表达、且符合岗位条件时可小批量投递。不必等 V5；更早满足条件也可以申请。不要等拒绝后才第一次看招聘要求。

第 12 周评估 Rust 切换门槛，并制定 Go 阶段前两周任务。核心通过即可进入 Go，未通过先修关键缺口；复杂 MQ、复制、极致优化等不作为额外门槛。岗位匹配、简历、笔试、算法、基础和项目追问分别复盘，样本过少时不把所有失败归因于语言。

## 后半年扩展边界

优先顺序：实习/真实协作 > Rust 与 Go 两个核心项目质量 > 第三项目数量。

- 系统方向：一个 HTTP Gateway，围绕超时、背压、限流、上游失败与性能开销。
- 可靠性方向：将订单通知模块演进为可靠投递流程，围绕重试、幂等、死信和恢复。
- AI Infra：仅在 HTTP、数据库、队列、部署和可观测性基础已验收，且研究/岗位需要时，考虑小型推理网关或模拟 Worker；不是本路线必须完成的第三项目。
- 不把 Kubernetes、Raft、完整数据库、多个消息中间件和深入 Tokio 源码列为前 12 周必做。

每周执行 [进度与复盘](progress.md)；每月重新阅读目标岗位。年度后续每日安排只在进入相应阶段时展开，避免一年日程成为负担。
