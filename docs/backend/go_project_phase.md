# Rust → Go：切换门槛与第二项目

更新日期：2026-10-13。学习者已明确选择先 Rust 后端项目，再 Go 后端项目。Go 阶段是确定的下一步，不再只是岗位反馈后的可选语言补课。

## 1. 两个阶段各自解决什么问题

第一阶段：用熟悉的 Rust，通过 Mini Order Service 学习 HTTP、数据建模、SQL、事务、并发正确性、权限、缓存、测试、部署和排障。先形成能解释的后端模型，预计预算 12 周。

第二阶段：在已有后端基础上，学习 Go 的语言和工程方式，并做一个完整项目。预计再用约 12 周，结合实际验收调整。SQL、事务与 HTTP 不重新从零学；Go 的 interface、error、defer、goroutine、channel、context、工具链和测试需要单独练习。

C++ 算法、基础复习与求职反馈跨两个阶段持续进行。没有开始的 Go 任务保持待执行，当前练习仍是 Rust HTTP/Axum。

## 2. Rust 项目何时可以结束第一阶段

以下门槛同时满足后进入 Go，不要求把 Rust 项目所有扩展做完：

- HTTP/API：能独立设计、实现和测试商品与订单路径，说明输入、状态码、错误与身份边界。
- 数据库：能自己写 SQL、migration、索引与事务，解释连接池和查询计划。
- 正确性：防超卖、事务回滚、同键重试与重复取消有测试，并能解释数据库层如何支撑不变量。
- 权限与缓存：用户不能操作他人订单；缓存失效/不可用行为和库存依据明确。
- 工程：有自动化测试、配置、日志和可复现部署；关键错误能够定位。
- 分析：至少一个失败实验与一份基本性能基线，注明条件和限制。
- 独立性：不用完整参考答案，能修改一个关键路径、预测一个变体并解释结果。

不以“代码编译”“接口能调通”作为毕业依据。未完成事项分为关键缺口与后续扩展：前者先修，后者记录后进入 Go。完整 Broker 集成、复杂任务调度、微服务、极限性能优化等属于扩展。

可靠任务若已经做到 V4，就带着实际失败经验进入 Go；若还没完成，Go 第二项目的通知模块继续学习这一问题，不在两个项目上同时赶工。

## 3. 第二项目暂定：团队协作与工单服务

这是当前建议的选题，进入 Go 阶段时确认，也可替换为难度相当的业务项目。选择它是为了在复用 HTTP/数据库基础的同时，练习权限、业务状态与协作流程。

起步技术栈：Go、标准库 net/http、MySQL、database/sql、Redis、Docker、Linux。先理解标准库请求/响应、context 和 SQL，再按实际需求选路由框架或查询工具；不同时引入多个框架。

Go module 独立管理，规划目录可为 `projects/go_issue_service`，不加入 Cargo workspace。现在不创建模块、下载依赖或生成实现。

| 版本 | 业务范围 | 核心难点与验收 |
|---|---|---|
| G0 | 内存项目/工单 API | Go 类型、interface/error、HTTP/JSON、测试；能独立增加同类接口 |
| G1 | MySQL 持久化、组织/成员、身份与角色 | 迁移、事务、权限矩阵、组织隔离；不能靠猜 ID 越权 |
| G2 | 工单状态、负责人、评论、并发更新 | 合法状态迁移、version/条件更新、评论权限；并发修改不能静默覆盖 |
| G3 | 查询分页、必要缓存、通知事件 | 游标分页、缓存失效、同事务产生事件、重试与幂等；重复消费无重复业务效果 |
| G4 | 工程交付、指标与故障分析 | context 超时/取消、优雅关闭、测试、部署、CI、基线与恢复实验 |

真实邮件、复杂全文搜索、多 Broker、微服务和完整协作平台均为选做；先实现一个组织下的完整流程，再验证多组织边界。

## 4. Go 阶段粗粒度任务

以原计划 Week 13～24 为预算。Rust 阶段顺延时整体后移，不按日期自动切换。

| 时间 | 学习与实现 | 验收证据 |
|---|---|---|
| W13～14 | Go 类型、slice/map、method/interface、error/defer、module、go test；小任务围绕项目模型 | 闭卷实现业务函数，解释值/引用与错误处理，不机械翻译 Rust |
| W15～16 | net/http、JSON、中间件、goroutine/channel/mutex、context；完成 G0 | 路由/业务测试、取消实验、race detector 观察；区分并发与并行 |
| W17～18 | database/sql、MySQL、migration、事务与组织权限；完成 G1 | 核心集成测试、越权测试、数据库错误/超时处理 |
| W19～20 | 状态迁移、乐观并发控制、分页、必要缓存；完成 G2/G3 核心 | 并发冲突、状态非法迁移、缓存失效与分页测试 |
| W21～22 | 可靠通知与恢复；Rust 已完成此主题则重点做 Go 实现对照 | 双写失败、重复消费、有限重试、重启恢复证据 |
| W23～24 | 部署/CI、指标、压测、故障报告与项目面试；完成 G4 | 新环境复现、请求取消/关闭语义、报告与简历证据 |

具体每日任务与中文主题材料在进入 Go 阶段前建立，根据 Rust 验收和可用时间定制，不提前假定后端基础均已掌握。

## 5. 迁移时必须主动比较

| 已有经验 | Go 阶段需要验证的差别 |
|---|---|
| Rust 所有权、Result、Drop | Go 值/指针、error、defer、资源生命周期；GC 不替代所有资源管理 |
| Tokio task 与 Future | goroutine 的执行与调度、阻塞行为、并发访问与 race 检测 |
| 异步 channel 与任务取消 | channel 所有者/关闭规则、context 的传递与协作取消 |
| SQLx、事务与连接池 | database/sql 的池/事务与上下文 API，驱动行为和错误处理 |
| Axum 路由/提取器 | net/http 请求/响应、middleware、身份传递与测试方式 |

在两项目之间保留同一种数据库，有助于把语言差别和数据库机制分开观察。后续按岗位需要再评估其他数据库。

## 6. 推荐资料

- 必读：[A Tour of Go](https://go.dev/tour/)，用于语言入门；每个概念立刻用于项目小函数。
- 必读：[net/http 官方文档](https://pkg.go.dev/net/http)，聚焦 Handler、Server、请求上下文和关闭。
- 必读：[Go 官方数据库教程](https://go.dev/doc/tutorial/database-access)，建立 database/sql 与 MySQL 访问模型；后续按官方文档补事务与取消。
- 必读：[Go Context](https://go.dev/blog/context)，学习请求范围的截止时间与协作取消。
- 实验必读：[Race Detector](https://go.dev/doc/articles/race_detector)，结合真实共享状态测试；没有报告竞态不等于所有执行都安全。

资料服务于项目，不先花数周只看语法。教学仍采用预测、独立实现、review、解释的循环。
