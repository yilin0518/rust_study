# Rust 后端与基础设施工程师一年学习路线

## 目标定位

目标岗位：**Rust 后端/基础设施工程师**。

重点能力：

- 高并发网络服务
- 数据库与存储
- 分布式系统
- 性能分析与可靠性
- 生产级后端工程

后续方向：将上述能力应用到 **AI 推理和计算基础设施**，包括推理网关、任务队列、批处理、资源调度、可观测性以及 Rust/Python 互操作。

## 路线设计原则

1. 先具备完整的后端工程能力，再进入专门的 AI Infra 主题。
2. 先观察阻塞、并发和系统限制，再引入高级框架。
3. 每个阶段都必须产生可运行、可测试、可解释的工程成果。
4. 持续演进少量核心项目，避免留下大量互不相关的演示代码。
5. Rust 是主要实现语言，同时学习岗位需要的 Linux、SQL、Python 和云原生工具。

## 阶段 1：网络、并发与异步基础（第 1～6 周）

### 学习内容

- TCP、UDP、socket、字节流与协议分帧
- 阻塞 I/O、线程和线程池
- 所有权在线程间的转移，`Send`、`Sync`
- `Arc`、`Mutex`、channel 和原子类型
- `Future`、`poll`、Waker、executor 和 reactor
- Tokio runtime、task、异步 I/O、取消、超时和背压
- 基础 Linux 进程、文件描述符、socket 和网络诊断

### 项目产出

- 阻塞式 Echo Server
- 一连接一线程的 Echo Server
- Tokio 多客户端 Echo Server
- 一个有明确消息边界的小型协议服务

### 完成标准

- 能解释阻塞线程与挂起异步任务的区别。
- 能解释 TCP 为什么需要应用层分帧。
- 能处理断连、部分读取、错误、超时和优雅退出。
- 能使用两个以上客户端验证并发行为。

## 阶段 2：生产级 Rust 后端（第 7～16 周）

### 学习内容

- HTTP、REST、状态码、Header 和请求生命周期
- Axum、Tower 中间件、Serde
- 统一错误模型、配置、日志和 tracing
- PostgreSQL、SQL、表设计、索引、事务和隔离级别
- SQLx、连接池、迁移和查询测试
- Redis 缓存、过期、一致性与缓存失效
- 鉴权、密码存储、输入校验和基础 Web 安全
- 单元测试、集成测试、端到端测试
- Docker、CI 和基础部署

### 核心项目 A：生产型后端服务

建议选择任务系统、作业平台或开发者服务作为业务场景。项目至少包含：

- REST API
- PostgreSQL 持久化与迁移
- Redis 缓存或任务状态
- 用户身份与权限边界
- 后台任务
- 结构化日志和 tracing
- 单元测试与集成测试
- Docker Compose 和 CI
- API 文档及架构说明

### 完成标准

- 能从需求设计数据模型和 API。
- 能解释事务、索引和连接池的作用。
- 能定位失败请求并通过日志或 trace 找到原因。
- 新环境能够根据 README 启动和验证服务。

## 阶段 3：数据库、存储与分布式系统（第 17～30 周）

### 学习内容

- 数据库内部基础：页、索引、B+Tree、LSM-Tree、WAL
- 缓存、批处理、零拷贝概念和磁盘 I/O
- RPC 与 gRPC、服务发现和负载均衡
- 消息队列与任务系统
- 超时、重试、幂等、限流、背压和熔断
- 一致性、复制、分片、故障模型
- Raft 的问题背景、核心状态与日志复制
- 分布式系统测试和故障注入

### 核心项目 B：演进式 Mini KV

按阶段增加能力：

```text
内存 HashMap
  -> 自定义有边界的网络协议
  -> 并发访问
  -> WAL 与重启恢复
  -> 索引或简单 SSTable
  -> 压测和性能分析
  -> 可选的复制实验
```

### 完成标准

- 能解释数据何时真正持久化。
- 能说明并发、崩溃和网络故障下的正确性边界。
- 能用基准和 profiler 找到至少一个真实性能瓶颈。
- 能说明系统当前不保证什么，而不只是展示成功路径。

## 阶段 4：可靠性、性能与云原生（第 31～40 周）

### 学习内容

- Prometheus 指标、OpenTelemetry tracing 和告警思想
- p50/p95/p99 延迟、吞吐量和饱和度
- CPU、内存、磁盘和网络性能分析
- `perf`、FlameGraph、strace、系统指标工具
- Docker 镜像、Kubernetes workload/service/config 基础
- readiness、liveness、优雅关闭和滚动升级
- CI/CD、故障排查、runbook 和容量估算

Windows 可继续作为日常开发环境，但项目需要在 Linux 环境中完成构建、运行和诊断。可使用 WSL2、devcontainer 或 Linux 虚拟机。

### 项目产出

- 为核心项目添加指标、trace、健康检查和压测。
- 编写一次从现象、证据到根因和修复的性能报告。
- 在容器环境部署服务，并演示优雅关闭与故障恢复。

## 阶段 5：AI 推理与计算基础设施（第 41～48 周）

### 先备能力

在这一阶段前，应已具备 Tokio、后端服务、数据库、队列、分布式基础、Linux 和可观测性能力。

### 学习内容

- Python 工程基础与 Rust/Python 通信方式
- PyTorch 与模型推理的基本流程
- token、batch、吞吐、首 token 延迟和显存的基本关系
- 在线 batching、队列、超时、取消和背压
- 推理 Worker、网关、控制面和数据面的职责
- GPU/CUDA 基础概念、GPU 指标与资源调度
- gRPC/HTTP 推理接口和流式响应
- 模型服务的可靠性、降级、限流和可观测性

### 核心项目 C：Rust AI 推理网关或调度器

```text
客户端
  -> Rust 推理网关
      -> 排队 / 限流 / batching / timeout
          -> Python 模型 Worker
              -> 流式或普通响应
```

项目需要记录请求数、队列长度、失败率和延迟，并能演示 Worker 故障或过载时的行为。早期可用小模型或模拟 Worker，不以训练大模型为目标。

## 阶段 6：求职交付与专项强化（第 49～52 周）

- 整理 2～3 个能深入讲解的核心项目。
- 为每个项目准备架构、关键取舍、故障案例和性能数据。
- 完善中英文 README、简历和项目介绍。
- 根据目标岗位补数据库、分布式系统或 AI Infra 的专项弱点。
- 进行 Rust、计算机基础、系统设计和项目深挖模拟面试。
- 持续投递校招、实习和基础设施岗位，不只搜索标题中含 Rust 的职位。

## 全年并行学习线

### 计算机基础

- 每周练习数据结构与算法。
- 持续复习操作系统、计算机网络、数据库和并发。
- 每两周完成一次系统设计或故障分析题。

### Linux 与工具

- 从第一阶段开始使用 Linux 环境运行项目。
- 熟悉 Git、Cargo、rustfmt、Clippy、测试、调试器和性能工具。

### 英文与开源

- 每周阅读一篇英文官方文档、issue、设计文档或论文摘要。
- 从文档、测试和小 bug 开始参与 Rust 后端、数据库或基础设施项目。
- 在进入求职阶段前争取形成至少一次被合并的有效贡献。

### 求职跟踪

- 每月收集一批目标岗位，提取技能关键词并更新差距表。
- 优先关注后端、数据库、存储、平台、云基础设施和 AI serving 岗位。
- 对校招和实习提前准备，因为申请窗口通常早于正式入职时间。

## 学习单元文档规则

`Day` 表示一个学习单元，不等于一个自然日。一个单元可以根据难度和掌握情况持续多天；完成依据是代码、实验结果和自己的解释，而不是时间。

每个学习单元开始前创建两份 Markdown：

1. `lesson_plans/` 中的教案：教学目标、顺序、预测点、误区和完成证据。
2. `study_materials/` 中的中文材料：知识点、代码片段、原理、实验步骤、预期结果和自测问题。

每份学习材料还应包含少量经过筛选的中文或英文参考资料：

- 优先选择官方文档、官方教程、经典书籍和高质量项目文档。
- 标注每份资料与当前单元的关系，以及建议重点阅读的章节。
- 区分“必读”和“选读”，避免一次堆积过多链接。
- 英文资料用于接触准确术语和真实工程文档，中文资料用于快速建立概念。
- 阅读服务于当前实验，不因为资料内容丰富而跳到后续学习单元。

只有当学习者能通过代码、实验结果和自己的解释提供完成证据时，才更新进度并进入下一单元。
